# CD deck v02 — 造型与交互探索

日期：2026-09-07
状态：供审阅的 imagegen 概念，不是已实现网页；本轮不修改应用代码、不部署。
生成方式：内置 image_gen；原始提示词见 prompts.md。

## 输出

- variants.png：A / NICKEL、B / CHAMPAGNE、C / GRAPHITE；三者是备选，不会同时放入网页。
- interaction-states.png：B 的待机、播放、退出、落位意向。
- 版式为对比而放大设备；实际 About 仍约 38% 内容宽、最大 480px，手机置于简介之后。

## 推荐

优先深化 B 的结构，采用接近 A 的较浅旧银/香槟金属，保留暖暗缝隙。Monitor 是旧 ABS，CD 是旧金属；统一光源、黑玻璃与使用痕迹，不强求同色。
A 更接近原始银色车载参考；C 更安静但在黑纸中容易失去轮廓。

## 图片不是机械定稿

生成图仍包含未经授权的 SCAN/ROOM/SEL 等装饰性标签，落地删除。
状态图第三格铰链关系需要几何样机验证，第四格落位前已经有频谱，与真实逻辑不符，落地不照抄。
对比板设备占比偏大，不能直接当作首页背景。
磨损不应平均喷满整块面板；仅沟槽、指尖常触位置和边缘少量变化。

## 交互定义

- 初始无声，屏幕低亮 READY。Hover 只提高局部可操作反馈，不自动播放、不随鼠标旋转整个机器。
- 播放键真实按压约 0.8–1.2mm（模型比例目标），随后回弹；音频确认 playing 后才走时与更新频谱。
- 音量旋钮竖向拖动映射音量与约 240° 旋转，模型本身旋转带动高光；点击与拖动分开判定（建议移动超过 5 CSS px 视为拖动），短按切静音；零音量不等于暂停。
- 拖动期间捕获指针，限制触屏滚动仅在旋钮命中区，取消/丢失指针需清理状态。提供可聚焦的原生音量 range 和独立静音按钮作为键盘/辅助技术控制。
- 普通 CD 的下一曲并不换碟。本方案的短换碟是一项明确的创作隐喻：每首试听曲作为一张虚拟唱片，而非声称仿真真实车载 CD 工作方式。若改为更严格硬件写实，可让下一曲仅寻轨，换唱片成为另一个明确动作，但本轮推荐保留用户要求的单一下一首换碟。
- 下一首目标约 1.1–1.3s（待样机调节）：约 0–200ms 淡出；200–500ms 前面板沿底铰链翻下 18–22°、显露深色碟仓；500–850ms 旧碟仅局部退出再收回，隐藏在仓内时替换曲目/盘面状态；850–1200ms 新碟落位、面板关闭，确认音频就绪后淡入。
- 固定正面摄像机下 CD 只显露窄弧，不展示违反视角的完整竖直圆盘。机构有导轨、铰链和持续存在的内仓，不以整体缩放/位移代替机械动画。
- 慢加载时闭合/安全落位后等候，显示 LOADING，不循环机械动作。失败显示重试/跳过。切换中可暂停；异步事件不能覆盖最后的暂停意图。
- 暂停中切换只换曲，不自动出声。自然结束复用切换流程。快速下一首锁住当前一次切换，不堆积队列。

## 技术分层（后续实施）

1. 实际音频控制继续复用首页级单播放器，不创建第二套 audio。分离用户播放意图、加载请求与可见机械阶段。
2. Three.js/R3F 拆出机壳、带真实 pivot 的面板、旋钮、实体键、CD、内仓、玻璃、显示面。更新网格变换而非用整张贴图冒充可动设备。
3. CanvasTexture 只负责显示窗的数字/曲名/真实音频频谱，是设备显示层，不是整台设备图。纹理细节用于粗糙度/法线/磨损，边缘倒角与玻璃凹进需要几何。
4. 现有 Framer Motion 用于外层 UI 反馈/浮动控件，不另引框架；同一时间轴驱动机械阶段，避免多个动画系统争夺同一属性。
5. 模型接近视口后加载；不可见/后台暂停绘制，音乐继续。减少动态效果保持静态设备和可用声音控制。
6. 从最终同一 3D 模型导出静态 poster，固定灯光；模型第一帧正确绘制后切换，避免像之前 Monitor 那样材质忽深忽浅。WebGL 失败保留 poster 与真实 HTML 控件。

## 实施检查点

1. 纯静态材质样机：以实际 About 比例检查正面轮廓、黑玻璃、旋钮与金属，不先叠动画。
2. 单一旋钮与按键样机：先失败测试后实现拖动/短按/键盘、pointer cancel；验证 mesh 真的转/压入。
3. 机械与音频：先测首次授权、暂停、换曲取消、失败、循环，再接完整铰链时间轴；不修改已有 terminal。
4. 整页验收：390×844、1440×900、1920×1080，减少动态效果/WebGL 失败/后台返回/移动端滚动/冷加载一致性；交付真实浏览器截图与短录屏。只用 localhost:3011，不推送部署。
